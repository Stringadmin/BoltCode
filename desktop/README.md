# BoltCode 桌面端

Windows 桌面版使用 Wails、Vue 和现有的 BoltCode Go Agent。源码沿用仓库根目录的 [MIT 许可](../LICENSE)。
随程序打包的 Noto Sans SC 字体使用 [SIL Open Font License 1.1](frontend/public/licenses/noto-sans-sc-OFL.txt)。

## 构建

需要 Windows x64、Git、支持 Vite 7 的 Node.js，以及 Go 1.26。脚本会使用 Go 1.26.10 或更新的兼容工具链。运行程序需要 Microsoft Edge WebView2 Runtime。

在仓库根目录运行 `pwsh -File desktop/build.ps1`，产物是 `desktop/bin/BoltCode.exe`。首次构建需要下载依赖。

## 使用

1. 打开有初始提交的 Git 仓库。之后可以从左上角切换最近项目，对话和草稿按项目保存。
2. 从左下角打开「设置 → 模型与渠道」。保存一套接口与 API Key 后，可在该渠道下添加多个模型。输入栏按渠道分组切换模型，思维强度随模型保存。具体可用档位由模型和接口决定。「测试连接」使用默认档发送一条简短请求。本机服务可以留空 API Key。
3. 发起对话。独立 Git worktree 在该对话首次发送时创建，随后核对并复用。构建模式每轮会保存撤回所需的检查点。限制访问下，命令逐条确认。完全访问需确认启用，授权按项目保存在 BoltCode 本地，重启后恢复该项目的选择。已识别的高风险命令和 Git 提交继续确认。点击权限按钮可切回限制访问。
4. 通过「查看改动」浏览文件列表和带行号的 Diff。确认合并前，桌面端会检查审查过的内容是否改变，以及目标分支是否干净。合并发生在本地 Git 仓库。
5. 在输入框键入 `@` 可搜索工作区文件，选中的文件会以标签显示。发送时把选中的 UTF-8 文本随消息发给当前模型。单文件最多 32 KB，每轮最多 6 个文件、合计 96 KB。
6. 构建轮次产生改动后，可以从对应消息打开「撤回本轮改动」，先预览再恢复文件。检查点由本地 Git 引用保存，重启后仍可用。若相关文件在该轮结束后又被修改或暂存，撤回会暂停。撤回涵盖检查点里的工作区文件，不回退 Git 提交、已合并的改动或工作区外的命令副作用。请避免在构建轮次执行时同时修改同一工作区。
7. 每轮读取对话工作区根目录下的 `AGENTS.md`，缺少时读取 `CLAUDE.md`。对话和「项目规则与检查」中显示文件来源。项目规则提供模型上下文，命令授权仍由软件处理。
8. 从项目菜单进入「项目规则与检查」，配置测试和类型检查。点改动审查的「运行检查」后，在对话 worktree 中依次执行。验证详情显示退出码、耗时和日志。改动快照、目标分支或命令变化后，已有结果会提示重跑。每条检查最长 3 分钟，合并由用户确认。
9. 在根目录的 `package.json` 声明带版本的 `packageManager` 后，桌面端会根据当前工作区记录包管理器以及已有的 `build`、`test` 脚本命令。点输入框旁的时钟图标可查看当前记忆和依据，展开消息下方的「本轮记忆」可回看当时发送给模型的内容。每轮都核对文件字段，撤回后会重新选择与恢复文件匹配的版本。项目检查通过记录只在运行检查的对话、原 Git 快照和原检查设置下适用。
10. 右键左侧对话可归档或删除。归档后可在「已归档」中查看，移出归档后可继续。删除需确认，会清除对话、草稿和记忆。项目列表中的垃圾桶可移除项目，也可勾选同时清除该项目的对话、草稿和设置。本地 Git 仓库及任务 worktree 文件都会保留。
11. 每轮的过程说明和工具记录集中在「执行过程」，运行时默认展开，结束后自动收起。点击标题可回看细节，最终回复和错误提示显示在下方。升级后的新轮次会记录实际用时。
12. 工具纠错会在本轮返回 JSON 格式、参数缺失或类型错误的具体提示。在后续一次工具调用验证修正有效后，BoltCode 将通用规则存到当前项目。Windows 下直接在 cmd.exe 运行受支持的 PowerShell 查询命令失败后，显式调用 PowerShell 并成功，也会记录一条规则。后续对话可在输入框旁的工作区记忆和消息的「本轮记忆」查看这些规则。
13. 在「设置 → 项目」查看检查命令、访问权限和归档项目。归档可从项目快捷菜单或设置执行，恢复后可从项目菜单重新打开。「设置 → 外观」可即时调整主题、强调色、背景、对话与代码字号，设置会本地保存。

桌面数据默认存放在 `%APPDATA%\BoltCode\desktop`，其中包括对话历史、任务 worktree 和加密后的桌面 API 密钥。首次使用可以沿用 BoltCode 当前模型配置。合并后的 worktree 保留供回看。

## 测试

在 `desktop` 目录运行 `go test ./workbench`。集成测试使用临时 Git 仓库和本地兼容模型端点，覆盖连接测试、命令确认、中断恢复和审查合并。可用 `go test ./workbench -run TestWorkspaceMemoryAcrossChatsChecksAndUndo` 单独回放双对话、检查、重启、撤回和合并。
